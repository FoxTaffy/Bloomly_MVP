# Загрузка файлов

## Лимиты по тарифам

Задаются перками в `backend/src/modules/payments/plan-perks.ts` и приходят на фронт в `/payments/config`
(зеркало для клиентской предпроверки — `frontend/src/lib/uploadLimits.ts`, сверяется тестом).

| Тариф | Фото | Видео и аудио | PSD / архивы (чат) | Фото |
|---|---|---|---|---|
| Free | 15 МБ | 100 МБ | недоступны | стандартное сжатие |
| Lite | 50 МБ | 500 МБ | недоступны | без сжатия |
| Pro | 50 МБ | 1 ГБ | 1 ГБ | без сжатия |
| Business | 50 МБ | 2 ГБ | 2 ГБ | без сжатия |

Папки вне тарифной сетки (аватары, баннеры 10 МБ; стикеры 100 КБ; рамки 5 МБ; жалобы 50 МБ; верификация 10 МБ) держат свой потолок.

## Как устроен приём

Два пути, выбор делает клиент по размеру (`frontend/src/lib/uploadMedia.ts`):

- **До 50 МБ** — один `POST /api/media/upload` (multipart).
- **Крупнее 50 МБ** — чанковая загрузка (`backend/src/modules/media/chunked.ts`): каждый запрос ≤ 25 МБ, поэтому
  проходит через Cloudflare (лимит тела 100 МБ на Free/Pro). Протокол:
  1. `POST /api/media/upload/init` `{ fileName, mimeType, totalSize, folder }` — тариф и лимит проверяются до пересылки
     данных (`413 FILE_LIMIT_EXCEEDED` / `403 FILE_TYPE_NOT_IN_PLAN`), создаётся сессия `uploadId` с временным файлом.
     Не больше 3 сессий на пользователя, место на диске проверяется заранее.
  2. `PATCH /api/media/upload/:uploadId` — часть (`application/octet-stream`) с заголовком `Upload-Offset`; смещение
     должно равняться принятому (иначе `409 OFFSET_MISMATCH` с `details.received`). Часть дописывается в конец файла,
     недописанная откатывается. Клиент повторяет часть до 3 раз и сверяется через `GET /api/media/upload/:uploadId`.
  3. `POST /api/media/upload/:uploadId/complete` — проверка сигнатуры и тот же пайплайн хранения; ответ тот же, что у
     обычной загрузки. `DELETE /api/media/upload/:uploadId` — отмена.
  4. Cron каждые 30 минут удаляет сессии без активности дольше 3 часов вместе с временными файлами.
  Состояние сессий — на диске (`UPLOAD_SESSIONS_DIR`, по умолчанию `$TMPDIR/bloomly-chunked`); API рассчитан на один
  инстанс (при нескольких каталог нужен общий).

Общая часть для обоих путей:

1. Тариф и самый большой его лимит определяются до чтения тела; заведомо большой `Content-Length` отсекается 413 сразу.
2. Файл читается потоком через `ByteLimiter` во временный файл. Лимит зависит от вида файла (фото / видео / документ):
   как только поток его превысил, приём обрывается, временный файл удаляется, ответ — `413 FILE_LIMIT_EXCEEDED`
   с `details.requiredTier`. Документы на тарифе без них — `403 FILE_TYPE_NOT_IN_PLAN`.
3. Таймаут — по простою (60 с без данных), а не на весь файл.
4. Видео и документы уходят в MinIO потоком с диска. Фото читает `sharp` с диском (`sequentialRead`, `rotate()` по
   EXIF Orientation); одновременно декодируется не больше `MAX_CONCURRENT_IMAGE_JOBS` фото.
5. «Фото без сжатия» (Lite+): отображаемая копия до 3840 px, webp качества 92, оригинал сохраняется отдельно
   (`posts/originals`). Free: 2000 px, качество 85.
6. **Оригиналы очищаются от метаданных без перекодирования** (`backend/src/lib/stripMetadata.ts`): из JPEG вырезаются
   APP1 (Exif/XMP), APP13 (IPTC) и комментарии, из PNG — `eXIf`/`tEXt`/`zTXt`/`iTXt`, из WebP — `EXIF`/`XMP`.
   Сжатые пиксели и ICC-профиль остаются бит-в-бит; при `Orientation ≠ 1` остаётся минимальный EXIF только с этим
   тегом. GIF сохраняется как есть. Из AVIF метаданные без перекодирования не убрать — оригинал не сохраняется.
   Ограничение: данные, дописанные после конца изображения (EOI / IEND), копируются как есть.
7. PSD и архивы принимают чат и посты (Pro и Business); тип проверяется по сигнатуре, файл хранится как
   `application/octet-stream` с `Content-Disposition: attachment` и безопасным расширением. В постах они показываются
   плашкой скачивания, а не в карусели; в превью (OG, ленты групп) не попадают.

## Прокси

- `frontend/nginx.conf` и `deploy/nginx/bloomly.conf`: `location = /api/media/upload` с `client_max_body_size 2048m`,
  `proxy_request_buffering off`, таймауты 600 с. Остальной `/api/` (в том числе части чанковой загрузки по 25 МБ)
  по-прежнему 100m.
- Cloudflare режет тело запроса на 100 МБ на тарифах Free/Pro — чанковая загрузка это обходит. Одиночный
  `POST /api/media/upload` крупнее 100 МБ через него не пройдёт, поэтому клиент шлёт такие файлы частями.
