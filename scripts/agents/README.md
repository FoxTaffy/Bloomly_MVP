# Агенты Bloomly

Два уровня: **агенты репозитория** (скрипты и GitHub Actions, этот каталог) и **агенты платформы** (бэкенд, `backend/src/modules/agents`).

## Репозиторий

| Агент | Что делает | Где работает |
| --- | --- | --- |
| Security (`secret-scan.mjs`) | Ищет токены, пароли, приватные ключи, `.env` в индексе, дереве, диапазоне коммитов и всей истории. Значения секретов в отчёт не попадают. | pre-commit, pre-push, Action `security-scan` (каждый push/PR + раз в неделю вся история) |
| Commit style (`commit-msg.mjs`) | Приводит заголовок к `type(scope): тема`, подбирает тип по ветке/словам/путям, чистит тело, не пускает секреты в текст коммита, добавляет трейлер `Build: X.Y.Z`. | commit-msg |
| Version (`version-bump.mjs`) | Поднимает версию сайта (`frontend/package.json`, её показывает шапка) и API от версии в `HEAD`. По умолчанию patch; `BUMP=minor` / `BUMP=major` — для фич и крупных релизов. | pre-commit |
| Release notes (`release-notes.mjs`, `post-discussion.mjs`) | Оценивает масштаб: `patch` (правки) → поста нет; `feature` (feat-коммиты на 6+ файлов) и `major` (breaking) → пост в Discussions (метка `updates`). Детали безопасности в тексте скрываются; необязательная правка текста через Claude (`ANTHROPIC_API_KEY`). | Action `release-agent` |
| Branch sorter (`branch-sorter.mjs`) | Раскладывает коммиты/PR/задачи по веткам `тип/область`. Локально: `plan` и `apply` (создаёт НОВЫЕ ветки `sorted/…`, существующие не трогает). В GitHub: метки `type:*`/`area:*` и подсказка в PR. | локально, Action `branch-sorter` |

Подключение хуков: `sh scripts/agents/setup-hooks.sh`. Пропустить на один коммит: `SKIP_AGENTS=1 git commit …`.
Тесты: `node --test scripts/agents/test/agents.test.mjs`.

**Ложное срабатывание сканера:** комментарий `secret-scan:ignore` в строке. **Уже утёкшие и перевыпущенные секреты** в старой истории перечислены в `secret-scan.baseline`.

**Важно про GitHub.** Workflows по `issues`, `pull_request_target`, `schedule` и `workflow_dispatch` запускаются только из файлов на **ветке по умолчанию** (сейчас `main` — витрина). Чтобы `branch-sorter` и еженедельная проверка работали, скопируйте `.github/workflows/*` в `main`. `security-scan` и `release-agent` на push работают из той ветки, в которую запушено. Для `release-agent` задайте переменную репозитория `RELEASE_BRANCHES` (ветки через пробел, по умолчанию `main`) и секрет `ANTHROPIC_API_KEY` (по желанию); Discussions должны быть включены.

## Платформа

### Агент верификации
Разбирает заявки без человека. Порядок: жёсткие проверки в коде (аккаунт не ограничен, условия верификации выполнены, доказательство не использовалось другим аккаунтом, есть изображения) → разбор изображений и профиля моделью Claude с принудительным ответом по схеме → итог в коде: одобрение только при уверенности ≥ 85 %, без признаков нейросети, с читаемой «сигной» там, где она нужна. Любое сомнение — отказ с причиной; повторная заявка через 24 ч.

Людям остаётся только то, что машине проверить нечем: ссылки на соцсети (`popular`) и заявки только с видео. Они остаются в очереди с пометкой «нужен модератор». Любое решение агента можно отменить кнопкой во вкладке «Верификация» (галочка снимается/выдаётся сразу).

Настройки (`.env` бэкенда):

| Переменная | Значение |
| --- | --- |
| `ANTHROPIC_API_KEY` | ключ API; без него агент выключен |
| `VERIFICATION_AGENT_MODE` | `off` · `shadow` (считает вердикт, ничего не применяет) · `auto` (по умолчанию при наличии ключа) |
| `AGENT_MODEL` | модель с поддержкой изображений, по умолчанию `claude-sonnet-5-5` |

Рекомендуемое включение: сначала `shadow` на пару дней, сравнить «одобрил бы/отклонил бы» с вашими решениями во вкладке, затем `auto`.

### Субагенты вкладок
`reports`, `support`, `ads`, `verification` — по одному на вкладку админки. Каждые 10 минут оценивают очередь (размер и возраст старейшей записи), пишут в журнал `AgentLog` только изменения состояния и показываются карточкой «Агенты вкладок» в обзоре. Это наблюдатели: решений по жалобам, рекламе и поддержке они не принимают.
Новый субагент — запись в `TAB_AGENTS` (`tabAgents.ts`).

API: `GET /api/agents`, `GET /api/agents/logs`, `POST /api/agents/verification/run` (админ), `PATCH /api/verification/admin/requests/:id/override`.
